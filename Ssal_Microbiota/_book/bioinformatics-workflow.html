2 Bioinformatics Workflow

The following is a summary of the Earth Hologenome Initiative (EHI) workflow used to standardize the sequencing of wild organisms. The bioinformatic pipeline is developed to generate metagenome-assembled genomes (MAGs) that can be annotated and analysed to understand microbiome functionality. The workflow management system uses Snakemake to automate the process. This is a Python based tool designed to handle complex dependencies between the input files, output files, and the software tools used to process the data. The following steps of the workflow are explained here, taken from EHI guideline,

  1. Data preprocessing: the pipeline begins by assessing and filtering raw sequencing data to remove low-quality reads, adapters, and contaminants. This step ensures the data’s reliability and quality.

  2. Splitting host and non-host data: the metagenomic fraction is separated from the host, by mapping the reads against a reference host genome.

  3. Metagenomic assembly: the remaining non-host reads are assembled into contigs or scaffolds using metagenomic assembly software. This step results in a set of contigs representing the genetic material of the microbial community.

  4. Binning: the assembled contigs are clustered into metagenome-assembled genomes (MAGs) based on sequence composition, coverage, and other characteristics.

  5. MAG Annotation: MAGs are annotated to determine their taxonomic identity and functional potential.

  6. Dereplication: MAGs are dereplicated to remove redundancy and retain only unique genomic representatives. This step ensures that each MAG represents a distinct microbial population or genome.

  7. Compositional overview: finally, to understand the composition of the gut microbiota in individual samples, the pre-processed reads from each sample are mapped against the dereplicated MAG catalogue. This step quantifies the abundance of each MAG in each sample, allowing for a comprehensive view of the microbial community composition.

2.1 Data preprocessing (step 1)

2.1.1 Quality-filtering

An efficient means to remove low-quality nucelotides, reads, and adapters, is to use fastp (Chen et al. 2018). Paired-end adapters are detected by finding the overlap of each pair, assuming that only one adapter exists in the data and that adapter sequences exist only in the read tails. A sliding window method is used to drop low-quality bases of each read’s head and tail. PolyG tails result with two-color chemistry sequencing (i.e. Illumina) where red and green florescence represent four bases (red = C, green = T, red+green = A, none 0 G). As synthesis continues and signal strength decreases, some bases are wrongly interpreted as G in the read tails.

fastp \                                       # Initialize fastp
    --in1 {input.r1i} --in2 {input.r2i} \     # Single-end reads (mandatory)
    --out1 {output.r1o} --out2 {output.r2o} \ # Paired-end reads (optional)
    --trim_poly_g \                           # Force polyG tail trimming   
    --trim_poly_x \                           # Enable polyX trimming in 3' ends
    --low_complexity_filter \                 # Complexity = % difference between bases
    --n_base_limit 5 \                        # Max number of N bases per read
    --qualified_quality_phred 20 \            # Min quality value of a base
    --length_required 60 \                    # Min read length
    --thread {threads} \                      # 
    --html {output.fastp_html} \              #
    --json {output.fastp_json} \              #
    --adapter_sequence {params.adapter1} \    #
    --adapter_sequence_r2 {params.adapter2}   #

2.1.2 Host mapping

Skin swabs were used, and so a large portion of host DNA is expected in addition to microbial reads (hernandez_contrasting_2025?; Eisenhofer et al. 2024). To separate host from microbial genomes, an index of the host genome is prepared to map it against a reference genome, otherwise the process will be very slow. Bowtie2 is used to align reads to a reference genome, and requires a Burrows-Wheeler transform (BWT) algorithm index before aligning to a reference genome. SAMtools is a a software that converts files between SAM, BAM, and CRAM formats (Danecek et al. 2021). Next, reads are mapped against a reference genome, followed by a split between reads that have been mapped and the reads that were not mapped. The mapped reads can be used for performing population genomic analyses, while the unmapped reads can be used for metagenomic analyses. For salamanders, the closest available reference genome is Pleurodeles waltl. The estimated divergence time between these species is ~65Myr, and so we must anticipate that they will likely be very divergent (zhang__2008?).

# Build host index
bowtie2-build \
    --large-index \                   # Build a large index
    --threads {threads} \             # 
        {input.genome} {output.index} #
        
# Map reads to catted reference using Bowtie2
bowtie2 \                     #
    --time \                  #
    --threads {threads} \     #
    -x {input.catted_ref} \   # The basename of the index for the reference genome.
    -1 {input.r1i} \          # Comma-separated list of files containing mate 1.fq
    -2 {input.r2i} \          # Comma-separated list of files containing mate 1.fq
| samtools view -b -@ {threads} - | samtools sort -@ {threads} -o {output.all_bam} - &&

# Extract non-host reads (note we're not compressing for nonpareil)
samtools view -b -f12 -@ {threads} {output.all_bam} \
| samtools fastq -@ {threads} -1 {output.non_host_r1} -2 {output.non_host_r2} - &&

# Send host reads to BAM
samtools view -b -F12 -@ {threads} {output.all_bam} \
| samtools sort -@ {threads} -o {output.host_bam} -

# Get % duplicates from host BAM
picard -Xmx{resources.mem_gb}g MarkDuplicates \
-I {output.host_bam} \
-O {output.markdup_bam} \
-M {output.markdup}

2.1.4 Prokaryotic fraction assessment

SingleM is a tool for profiling shotgun metagenomes. It shows good accuracy in estimating the relative abundances of microbial community members, and has a particular strength in dealing with novel lineages. This is used to estimate what proportion of the reads are prokaryotic. SingleM microbial fraction (SMF) estimates the quantity of bacterial and archaeal DNA in metagenomic datasets based on the detection of reads encoding microbial single copy marker genes. An advantage of this approach is that it does not require any knowledge of non-microbial genomes such as Eukaryota or viruses, which are often missing from reference genome databases. (Eisenhofer_2024?)

#Run singlem pipe
singlem pipe \
    -1 {input.non_host_r1} \
    -2 {input.non_host_r2} \
    --otu-table {params.pipe_uncompressed} \
    --taxonomic-profile {output.condense} \
    --threads {threads}

#Run singlem read_fraction
singlem read_fraction \
    -1 {input.non_host_r1} \
    -2 {input.non_host_r2} \
    --input-profile {output.condense} \
    --output-tsv {output.read_fraction} \
    --output-per-taxon-read-fractions {params.read_fraction_taxa}

2.2 Assembly & Binning (steps 2-4)

2.2.1 Metagenomic assembly

Pre-processed reads are then assembled into contigs then clustered into bins to reconstruct draft bacterial genomes known as metagenome-assembled genomes or MAGs. Unlike traditional genome sequencing, where a single organism’s genome is targeted, metagenomics focuses on the genetic material of all microorganisms present in a given sample. A popular metagenome assemblers is Megahit (li_2016?) that allows removing contigs below a certain size. Due to the large computational requirements in the EHI, the default metagenomic assembler we use is Megahit.

megahit \
    -t {threads} \                #
    --verbose \                   #
    --min-contig-len 1500 \       # minimum length of contigs to output
    -1 {input.r1} -2 {input.r2} \ #
    -f \
    -o {config[workdir]}/{wildcards.PRB}_{wildcards.EHI}_assembly

Quast is then used to obtain some general statistics of the assemblies to decide whether they look meaningful to continue with downstream analyses (gurevich_2013?). QUAST can evaluate assembly quality without a reference genome.

quast \
    -o {output.report} \
    --threads {threads} \
    {input.assembly}

2.2.2 Assembly mapping

To group contigs into MAGs, binners require contig coverage information to decide which contig belong to which bin. This type of data is generated by mapping pre-processed metagenomic reads against the metagenomic assembly. CoverM (Aroney et al. 2025) calculates coverage of genomes/MAGs or individual contigs by read mapping, its input can either be BAM files sorted by reference, or raw reads and reference genomes in various formats.

# Construct a host index  
bowtie2-build \
    --large-index \
    --threads {threads} \
    {input.contigs} {input.contigs}

# Map reads to assembly using Bowtie2
bowtie2 \
    --time \
    --threads {threads} \
    -x {input.contigs} \
    -1 {input.r1} \
    -2 {input.r2} \
| samtools sort -@ {threads} -o {output}

# Using coverM, generate the assembly coverage data required for downstream binning steps.
coverm genome \                               
      -b {input.bam} \                        #
      --genome-fasta-files {input.contigs} \  #
      -m relative_abundance \                 # Method(s) for calculating coverage.
      -t {threads} \                          # 
      --min-covered-fraction 0 \              # Genomes with coverage below this are reported as 0 coverage.
      > {output.coverm}                       

#Run coverm for the eukaryotic assessment pipeline
coverm genome \
      -s - \                                  # Character separator between genome and contig names.
      -b {input.bam} \                        #
      -m relative_abundance count mean covered_fraction \
      -t {threads} \                          #
      --min-covered-fraction 0 \              #
      > {output.euk}

2.2.3 Ensemble binning

Metagenomic binning is the bioinformatic process that attempts to group metagenomic sequences into putative bacterial genomes. Dozens of binning algorithms exist, and performance is largely dependent on the specific properties of each sample. Subsequently, many researchers opt for ensemble approaches whereby assemblies are binned using multiple algorithms, followed by a refinement step that merges all generated information to yield consensus bins. Here, three algorithms are used:

2.2.3.1 Metabat

MetaBAT2 (kang_2015?) specialises in clustering metagenomic contigs into genome bins by considering both sequence composition and differential coverage across samples. It employs a likelihood-based approach to estimate the probability of contigs belonging to the same genome, allowing for the identification of distinct bins for individual microorganisms. MetaBAT2 is well-regarded for its ability to handle complex microbial communities and is widely used in metagenomic research for its binning accuracy.

# summarise contig depths
jgi_summarize_bam_contig_depths \
     --outputDepth {params.outdir}/metabat_depth.txt {input.bam} # file with contig by bam depth matrix

# Run metabat2
metabat2 \
     -i {input.contigs} \                   # 
     -a {params.outdir}/metabat_depth.txt \ # mean and variance of base coverage depth
     -o {params.outdir}/metabat2_bins/bin \ # base file name and path for each bin
     -m 1500 \                              # Minimum size of a contig for binning
     -t {threads} \                         #
     --unbinned                             # generate [outFile].unbinned.fa file

2.2.3.2 Maxbin

MaxBin2 (wu_2016?) is a metagenome binning software that utilises a combination of tetranucleotide frequency analysis and abundance information obtained from read mapping to identify distinct genomic bins representing different microorganisms within a metagenomic sample. MaxBin2 is known for its efficiency and accuracy in binning metagenomic contigs, making it a valuable tool for characterising microbial communities in various environments.

# summarise contig depths
jgi_summarize_bam_contig_depths \
    --outputDepth {params.outdir}/mb2_master_depth.txt \
    --noIntraDepthVariance \      # Do not include variance from mean depth along the contig
    {input.bam}

#calculate total numper of columns
A=($(head -n 1 {params.outdir}/mb2_master_depth.txt))
N=${{#A[*]}}

# split the contig depth file into multiple files
if [ -f {params.outdir}/mb2_abund_list.txt ]; then rm {params.outdir}/mb2_abund_list.txt; fi
for i in $(seq 4 $N); do
    sample=$(head -n 1 {params.outdir}/mb2_master_depth.txt | cut -f $i)
    grep -v totalAvgDepth {params.outdir}/mb2_master_depth.txt | cut -f 1,$i > {params.outdir}/mb2_${{sample%.*}}.txt
    if [[ {params.outdir} == /* ]]; then
        echo {params.outdir}/mb2_${{sample%.*}}.txt >> {params.outdir}/mb2_abund_list.txt
    else
        echo {params.outdir}/mb2_${{sample%.*}}.txt >> {params.outdir}/mb2_abund_list.txt
    fi
done

# Run maxbin2
run_MaxBin.pl \
    -contig {input.contigs} \             # 
    -markerset 107 \                      # marker gene sets, 107 (default) or 40
    -thread {threads} \                   #
    -min_contig_length 1500 \             # Default 1000
  -out {params.outdir}/maxbin2_out/bin \  # list of abundance files
  -abund_list {params.outdir}/mb2_abund_list.txt

mkdir -p {params.outdir}/maxbin2_bins
for i in {params.outdir}/maxbin2_out/*.fasta;
    do mv $i {params.outdir}/maxbin2_bins/$(basename ${{i/.fasta/.fa}});
done

2.2.3.3 CONCOCT

CONCOCT [(alneberg_?) _2014] is a metagenomic binning software that utilises differential coverage and sequence composition to cluster contigs into genome bins. Notably, CONCOCT is capable of separating closely related strains, and suitable for exploring fine-scale diversity within microbial communities.

cut_up_fasta.py {input.contigs} 
    -c 10000                            # Chunk size
    --merge_last                        # Concatenate final part to last contig
    -b {params.outdir}/assembly_10K.bed #
    -o 0                                # Overlap size
    > {params.outdir}/assembly_10K.fa   

concoct_coverage_table.py {params.outdir}/assembly_10K.bed {input.bam} > {params.outdir}/concoct_depth.txt

concoct \
    -l 1500 \                                             # Min sequence length threshold
    -t {threads} \                                        # 
    --coverage_file {params.outdir}/concoct_depth.txt \   # specify the coverage file
    --composition_file {params.outdir}/assembly_10K.fa \  # specify the composition file
    -b {params.outdir}                                    #

merge_cutup_clustering.py {params.outdir}/clustering_gt1500.csv > {params.outdir}/clustering_gt1500_merged.csv
mkdir -p {params.outdir}/concoct_bins
python {config[codedir]}/scripts/metawrap_split_concoct_bins.py {params.outdir}/clustering_gt1500_merged.csv {input.contigs} {params.outdir}/concoct_bins

2.3 MAG Annotation (step 5)

Once bacterial genomes have been binned and generated, thay can be annotated both taxonomically and functionally.

2.3.1 Taxonomic annotation

MAGs can be taxonomically annotated using different algorithms and reference databases, but the Genome Taxonomy Database (GTDB) and associated taxonomic classification toolkit (GTDB-Tk) (chaumeil_2022?; parks_2022?) have become the preferred option for many researchers. The classify workflow consists of four steps,

  1. ani_screen - compares user genomes against a Mash database composed of all GTDB representative genomes.
  2. identify - calls genes using Prodigal, and uses HMM models to identify markers used for phylogenetic inference
  3. align - concatenates the aligned marker genes and filters ~5,000 amino acids.
  4. classify - uses pplacer to find the maximum-likelihood placement of each genome in the GTDB-Tk reference tree.
# Run GTDB-tk:
gtdbtk classify_wf \              # classify workflow 
    --genome_dir {params.bins} \  #
    --extension "gz" \            #
    --out_dir {params.outdir} \   #
    --cpus {threads} \            #
    --skip_ani_screen             #

2.3.2 Functional annotation

Functional annotation identifies putative functions of genes present in MAGs based on information available in reference databases. Multiple tools exist that perform all these procedures in a single pipeline. For instance, DRAM (shaffer_2020?) performs the annotation using Pfam, KEGG, UniProt, CAZY and MEROPS databases.

# Assigns database identifiers to genes
DRAM.py annotate \
        -i {input.mag} \
        -o {params.outdir} \
        --threads {threads} \
        --min_contig_size 1500

# Distill curates annotations into useful functional categories
DRAM.py distill \
        -i {params.outdir}/annotations.tsv \
        --rrna_path {params.outdir}/rrnas.tsv \
        --trna_path {params.outdir}/trnas.tsv \
        -o {params.distillate}

2.4 Dereplication (step 6)

2.4.1 MAG Dereplication

Dereplication is the reduction of a set of MAGs based on high sequence similarity between them to minimize computational demands, inflated diversity, or unspecific read mapping. Dereplication is based on pairwise comparisons of average nucleotide identity (ANI) between MAGs, implying a quadratic increase in comparisons. A popular tool used for dereplicating MAGs is dRep, which combines the fast yet innacurate algorithm MASH with the slow but accurate gANI computation to yield a fast and accurate estimation of ANIs between MAGs. An optimal threshold that balances between retaining genome diversity while minimising cross-mapping issues has been found to be 98% ANI.

dRep dereplicate \                    # dereplicates a set of genomes
      {config[workdir]}/drep \        #
      -p {threads} \                  #
      -comp 50 \                      # Minumum genome completeness
      -sa {config[ani]} \             # ANI threshold to form secondary clusters
      -g {config[magdir]}/*.fa.gz \   # genomes to filter in
      --genomeInfo mags_formatted.csv

2.4.2 Mapping to MAG catalogue

Relative abundance information is used to measure how abundant each bacteria is among a sample. To achieve this, reads from each sample must be mapped to the MAG catalogue. Identical to the assembly read-mapping section, but using the MAG catalogue as a reference database rather than the metagenomic assembly. First, reads are mapped to the MAG catalogue to generate BAM or CRAM mapping files. Then, mapping files are used to extract quantitative read-abundance information in the form of a table in which the amount of reads mapped to each MAG in each sample is displayed.

All MAGs need to be concatenated into a single file, which will become the reference MAG catalogue or database.

# Concatenate MAGs
cat {config[workdir]}/drep/dereplicated_genomes/*.fa.gz > {config[workdir]}/mag_catalogue/{config[dmb]}_mags.fasta.gz

The MAG catalogue needs to be indexed before the mapping.

# Index the coassembly
bowtie2-build \
      --large-index \
      --threads {threads} \
      {output.mags} {output.mags}

Then, the following step needs to be iterated for each sample, yielding a BAM mapping file for each sample.

bowtie2 \
    --time \
    --threads {threads} \
    -x {input.contigs} \
    -1 {input.r1} \
    -2 {input.r2} \
| samtools sort -@ {threads} -o {output}

Finally, CoverM can be used to extract the required stats, such as relative abundance and covered fraction per MAG per sample.

#Relative abundance
coverm genome \
    -b {input} \                # Path to BAM file(s).
    -s ^ \                      # Character separator genome names from contig names. 
    -m relative_abundance \     # Method(s) for calculating coverage
    -t {threads} \              #
    --min-covered-fraction 0 \  #
    > {output.mapping_rate}

#MAG coverage
coverm genome \
    -b {input} \
    -s ^ \
    -m count covered_fraction \
    -t {threads} \
    --min-covered-fraction 0 \
    > {output.count_table}
